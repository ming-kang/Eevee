# 安全运行

Eevee 采用本地 YOLO 方式工作：Worker 与 Engine 同属你这个用户的本地信任边界，工具不逐次请求授权，也没有内置沙箱。Worker 的 `bash`、`write`、`edit` 能做的事，就是 Engine 进程能做的事。

这一页说明 Eevee 自己做了哪些防护、没做哪些，以及怎样降低风险。

## 选择运行方式

| 情况 | 建议 |
|---|---|
| 你自己的仓库和文件，在可信的机器上 | 直接运行，工作目录放进版本控制 |
| 不受信任的仓库、文档或网页内容 | 在容器或虚拟机里运行整个 Eevee，只挂载需要的目录 |
| 长时间无人值守 | 在隔离环境里运行，并限制网络和凭据 |
| 共享的机器 | 不要运行；Eevee 只按操作系统用户隔离 |

需要隔离时，应当在操作系统、容器或虚拟机层隔离整个 Engine。为某个角色启用或停用扩展只决定它能用哪些能力，不是权限系统。

## 本地接口的防护

Engine 的本地接口能让 Worker 执行任意命令，所以一旦被其他程序或网页调用，就等于远程执行任意命令。Eevee 为此做了这些限制：

- **只监听回环地址**：只绑定 `127.0.0.1`，并要求请求的 `Host` 和 `Origin`（如果有）都是回环地址，防止 DNS 重绑定和网页跨站请求。
- **全部接口都要鉴权**：只有健康检查和授权码兑换不需要 token。命令行使用 `runtime/cli-token` 里的 token，浏览器使用会话 token，两者都放在 `x-eevee-token` 请求头里。
- **敏感操作只允许命令行**：停止 Engine、生成授权码、保存凭据只接受 CLI token，浏览器会话无法调用。
- **浏览器授权**：`eevee web` 生成的授权码 90 秒内有效、只能用一次。会话 12 小时无操作后过期，Engine 只保存会话 token 的哈希。
- **实时流**：WebSocket 同样只接受回环地址。浏览器无法给 WebSocket 设置请求头，所以 token 放在子协议里，Engine 只回应 `eevee.v1`，不会回显 token。

## 子进程的环境变量

`bash` 命令、后台作业和 stdio MCP 服务器不继承 Engine 的全部环境变量，只继承 `PATH`、`HOME`、`TEMP`、`LANG` 等基础变量（完整列表见 [环境变量](environment-variables.md#子进程继承的变量)）。provider 的 API key 等 Engine 持有的凭据不会主动传给它们。

这只能减少意外泄漏，不是隔离边界：Worker 仍然可以读取你的文件，包括 `~/.eevee/auth.json`。

## 私有文件

`auth.json`、`settings.json`、`runtime/cli-token`、`runtime/sessions.json` 等私有文件都先写临时文件再改名，原子替换；在 POSIX 系统上权限为 `0600`。

## 扩展与 MCP 服务器

- **用户扩展**在 Engine 进程里运行，拥有 Engine 的全部权限，能看到所有项目的对话和凭据。只放你信任的代码。
- **stdio MCP 服务器**作为 Engine 的子进程运行，`env` 里引用的变量会传给它。**HTTP MCP 服务器**会收到调用它的角色传来的参数，以及你在 `headers` 里配置的 token。
- MCP 工具返回的内容和网页、文件一样会进入模型上下文，可能包含提示注入。

## 不受信任的内容

工作目录里的文件、网页、MCP 工具输出、对话记录和记忆笔记都可能包含诱导模型执行危险操作的文字。Eevee 的提示词把对话记录和记忆当作数据而不是指令，但这不能完全防止提示注入。处理不受信任的内容时，在隔离环境里运行。

## 降低影响、方便恢复

- 把工作目录放进 Git，或者定期备份，出问题时可以看 diff、回退改动。
- 记忆库本身是 Git 仓库，记错的笔记用 `eevee memory revert` 撤销，见 [管理记忆](memory.md#查看历史和撤销)。
- 不要把高权限凭据放进运行 Engine 的环境；需要时为 Eevee 单独申请权限受限的 key。
- 定期查看 `eevee project usage`，及早发现异常的花费。
- 用 [`maxTurns`](capabilities.md#限制每次运行的轮次) 限制 Worker 每次运行的轮次，避免失控的循环。
