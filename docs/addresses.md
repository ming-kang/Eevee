# 资源地址

资源地址是 Eevee 引用持久对象的统一写法。所有角色都用 [`read`](tools.md#read) 按地址读取；报告、记忆笔记、截断标记和开篇里的工单一览也都用地址指路，模型可以顺着地址一层层找回旧内容，不需要把它们放进上下文。

## 地址一览

| 地址 | 内容 |
|---|---|
| 普通路径，如 `draft.tex`、`/data/run1.csv` | 文件。相对路径以工作目录为准 |
| `ticket://` | 工单列表，新的在前，每行为 `t3 [open] 标题` |
| `ticket://t3` | 一张工单的全部字段，包括它的 Worker 对话编号 |
| `report://t3` | 一张工单的全部报告 |
| `report://t3#2` | 一张工单的第 2 份报告 |
| `transcript://1` | 一个对话的记录，按条目分页。`1` 是 Router 的对话 |
| `transcript://1/42` | 一个对话里第 42 个条目的全文 |
| `memory://project/MEMORY.md` | 项目记忆库里的文件 |
| `memory://global/MEMORY.md` | 全局记忆库的 `MEMORY.md` |
| `job://j7` | 后台作业的状态和完整输出 |
| `models://` | 默认模型、可用模型的参数和你记录的使用经验 |

编号的格式：工单为 `t1`、`t2`…，作业为 `j1`、`j2`…，报告在同一张工单内从 1 递增，对话和条目是非负整数。格式不对的地址会返回错误并说明正确写法。

Worker 对话的编号写在 `ticket://t3` 的 `conversationId` 字段里。

## 分页

`read` 的结果一律分页，结果末尾给出继续读取的写法。

| 内容 | 默认 | 上限 | `offset` 的含义 |
|---|---|---|---|
| 文件 | 2000 行或 50 KB，先到为准 | — | 行号 |
| 工单列表、对话记录 | 20 项 | 50 项 | 工单列表为第几项；对话记录为条目编号 |
| 其他文本（工单、报告、记忆、作业、模型） | 4000 字 | 8000 字 | 字符位置 |

## 读对话记录

`transcript://<对话>` 不带 `offset` 时读最新的条目，带 `offset` 时从那个条目编号读起。每个条目显示为一行预览：

```text
#40 user: 先别动 figures/ 目录，我还在改
#41 assistant: 好的，我会让 t2 只改 results/。
#42 tool: 已给 t2 追加指令。

[更早的条目：read("transcript://1", offset: 20)；单条全文：read("transcript://1/<条目编号>")]
```

需要某个条目的完整内容时，读 `transcript://<对话>/<条目>`。重置后的开篇里带有最近几轮原文，其中超过 1500 字的工具输出会被截短，截断标记里附有这个地址。

## 搜索

`read` 的 `query` 参数只返回包含这段文本的行，可以用于文件、工单列表、对话记录等。

- `read ticket://`，`query: "[open]"`：只看未结的工单；
- `read results/log.txt`，`query: "ERROR"`：只看出错的行；
- `read transcript://1`，`query: "配色"`：在 Router 对话最新的一页里找提到配色的条目。

对 `transcript://` 使用 `query` 时，只在当前这一页（默认最新 20 个条目）里过滤；要找更早的内容，配合 `offset` 翻页。文件加 `query` 时，结果按字符分页，`offset` 是字符位置而不是行号。

## 在报告和记忆里使用地址

- 报告的输入、产物和续读都写成地址，Router 和其他 Worker 可以直接读，不需要转述。
- 记忆笔记的每条经验都附上来源地址和日期，比如 `（ticket://t12，2026-11-16）`。
- 整理工单的输入列出待整理记录的地址和起读位置，比如 `transcript://1（Router，从 offset 42 读起）`。
