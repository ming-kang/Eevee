# 日常使用

Eevee 的日常使用围绕一个 Router 展开：你告诉它要做什么，它建工单、安排 Worker、处理报告，只在必须由你决定时才来问你。还没有安装或连接模型的话，可以先阅读 [快速开始](quickstart.md)。

## 启动和停止

| 动作 | 命令 |
|:-:|:-:|
| 启动 Engine 并打开面板 | `eevee` |
| 只在后台启动 Engine | `eevee start` |
| 查看运行状态和项目列表 | `eevee status` |
| 停止 Engine | `eevee stop` |

Engine 停止后，进行中的工作会在下次启动时接着进行。升级 Eevee 时，装好新版本后先 `eevee stop` 再 `eevee start` 即可，不需要等工单做完。

注意：`eevee stop` 会终止正在运行的后台作业。重启后，相关的 Worker 会收到通知，自行决定是否重跑。有耗时的作业在跑时，先在面板里确认：项目的悬停卡片和右栏的“作业”标签会列出正在运行的后台作业。

## 打开面板

```bash
eevee
```

Engine 没有运行时先启动它，然后生成一个一次性授权码，在浏览器里打开带授权码的地址。Engine 已经在运行时，`eevee web` 的效果相同。授权码 90 秒内有效；页面换到 token 后会立刻从地址栏移除它，并把 token 记在这个浏览器里。之后新开标签页、打开书签、重启浏览器或 Engine 都不用重新授权；换了浏览器或 Engine 换了端口时，再运行一次 `eevee`。

没有授权时打开面板地址，页面只显示连接说明。

面板的布局、各个页面和快捷键见 [使用面板](web.md)。命令行只负责启动、停止和打开面板，其余操作都在面板里完成；想在脚本里操作，可以直接调用 [HTTP 接口](http-api.md)。

## 和 Router 对话

在面板里选中项目，在主对话里直接说你要做的事。需求清楚时 Router 会直接建单；不清楚时，它先从工作目录和记忆里查，只有真正要你拍板的分歧才会提问。

Router 正在工作时，你发的消息会在它当前这批工具调用结束后立即被看到，不需要等它说完。

有待回答的问题时，面板用问题卡片代替输入框。这时先回答问题，或者点“稍后”把卡片收成一行提示条，再发消息。

Router 本身不读写工作目录、不执行命令。耗时的工作都会变成工单，由 Worker 在后台完成。

## 回答问题

要你决定时，Router 会提一轮编号问题，每题附推荐答案。面板上，问题卡片会出现在输入框的位置，推荐选项已预先选中。

问题可能来自 Router 自己，也可能来自某张工单。回答工单的问题时，答案直接投给那个 Worker，不经过 Router 转述。

## 查看工单

面板右栏的“工单”标签列出项目的全部工单，分成待回答、进行中和已结单三组。每张工单显示编号、标题和 [阶段](tickets.md#工单阶段)，点开进入它的 Worker 对话。

只有 `answer` 阶段要你处理，即工单在等你回答问题。其他阶段都由 Router 和 Engine 自动推进；Router 推进不了时，会向你提问。

## 观察和介入 Worker

在面板上点开任意工单，可以看到它的 Worker 完整、实时的执行过程：每次工具调用、命令输出和报告。

你可以直接介入：

| 想做什么 | 方式 |
|:-:|:-:|
| 调整它正在做的事 | 发送引导消息：当前这批工具调用结束后立即被看到 |
| 在它做完这一轮后追加工作 | 发送排队消息：这一轮结束后再开始新的一轮 |
| 停下当前这一轮 | 打断：工单仍保持打开 |

Worker 空闲时，引导和排队效果一样，都会直接开始新的一轮。你直接给 Worker 发的消息，Router 也会看到一条记录，但不会被唤醒。

直接介入不是审批流程。Worker 本来就不会在每次工具调用前等你确认，介入只是让你在需要时改变方向。

## 重试失败的一轮

模型请求重试用尽或者超出轮次上限时，这一轮会以失败结束，对话视图会显示失败原因。工单的 Worker 失败时，Engine 还会记一份 `failed` 报告并唤醒 Router，由 Router 决定让它继续还是取消工单。

你也可以在面板上直接重试失败的那一轮，Router 和 Worker 都可以。

## 查看花费

左栏底部的“用量”打开当前项目的用量页：第一行是合计的费用、输入、输出和缓存命中，下面按模型、按对话（Router 和每张工单）分别列出。

provider 报告了实际计费时用实际金额，否则按模型目录里的价格估算。

## 查看日志

`eevee start` 启动的 Engine 把输出追加到 `~/.eevee/runtime/engine.log`，包括 MCP 连接失败、扩展加载错误和配置问题。实时查看：

```bash
tail -f ~/.eevee/runtime/engine.log
```

遇到问题时，先看 [排查问题](troubleshooting.md)。
