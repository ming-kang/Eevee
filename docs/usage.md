# 日常使用

Eevee 的日常使用围绕一个 Router 展开：你告诉它要做什么，它建工单、安排 Worker、处理报告，只在需要你决定时才来问你。还没有安装或连接模型的话，可以先阅读 [快速开始](quickstart.md)。

## 启动和停止

| 动作 | 命令 |
|:-:|:-:|
| 在后台启动 Engine | `eevee start` |
| 查看运行状态和项目列表 | `eevee status` |
| 停止 Engine | `eevee stop` |

Engine 停止后，进行中的工作会在下次启动时接着进行。升级 Eevee 时，装好新版本后先 `eevee stop` 再 `eevee start` 即可，不需要等工单做完。

注意：`eevee stop` 会终止正在运行的后台作业。重启后，相关的 Worker 会收到通知，自行决定是否重跑。有耗时的作业在跑时，先用 `eevee project board` 确认没有标着后台作业的工单。

## 打开面板

```bash
eevee web
```

这条命令生成一个一次性授权码，并在浏览器里打开带授权码的地址。授权码 90 秒内有效、只能用一次；页面换到会话后会立刻从地址栏移除它。会话 12 小时无操作才过期。Engine 重启后，已授权的页面一般可以继续使用；页面提示需要授权时，重新运行 `eevee web`。

直接打开不带授权码的地址时，页面只显示连接说明。

面板的布局、各个页面和快捷键见 [使用面板](web.md)。面板和命令行覆盖的操作：

| 操作 | 面板 | 命令行 |
|:-:|:-:|:-:|
| 给 Router 发消息 | ✓ | ✓（`eevee project say`） |
| 查看 Router 的回复 | ✓ | |
| 回答问题 | ✓ | |
| 观察 Worker、发消息、打断、重试 | ✓ | |
| 查看后台作业的日志、终止作业 | ✓ | |
| 新建项目、查看花费 | ✓ | ✓ |
| 记忆的历史、diff 和撤销 | ✓ | ✓（`eevee memory`） |
| 默认模型、角色能力、重新加载 MCP | ✓ | ✓ |
| 登录 provider | | ✓（`eevee model login`） |

想在脚本里做命令行不支持的操作（比如回答问题、给 Worker 发消息），可以直接调用 [HTTP 接口](http-api.md)。

## 和 Router 对话

在面板里选中项目，在主对话里直接说你要做的事。需求清楚时 Router 会直接建单；不清楚时，它先从工作目录和记忆里查，只有真正需要你拍板的分歧才会提问。

Router 正在工作时，你发的消息会在它当前这批工具调用结束后立即被看到，不需要等它说完。

有待回答的问题时，面板用问题卡片代替输入框。这时先回答问题，或者点“稍后”把卡片收成一行提示条，再发消息。

终端里也可以给 Router 发消息：

```bash
eevee project say <project> 先别动 figures/ 目录，我还在改
```

Router 本身不读写工作目录、不执行命令。耗时的工作都会变成工单，由 Worker 在后台完成。

## 回答问题

需要你决定时，Router 会提一轮编号问题，每题附推荐答案。面板上，问题卡片会出现在输入框的位置，推荐选项已预先选中。

问题可能来自 Router 自己，也可能来自某张工单。回答工单的问题时，答案直接投给那个 Worker，不经过 Router 转述。

`eevee project board <project>` 会在工单列表前列出所有待回答的问题。命令行目前只能列出问题，不能回答。

## 查看工单

```bash
eevee project board <project>
```

每张工单显示编号、[阶段](tickets.md#工单阶段) 和标题，有后台作业在跑时也会注明。已结单的工单也会列出，通常显示为 `idle`。例如：

```text
? q2 结果图用对数坐标还是线性坐标？
t1 [working] 打磨论文草稿
t2 [review] 运行仿真（1 个后台作业）
t3 [waiting] 补充参考文献
```

需要你出面的阶段只有 `answer`，即工单在等你回答问题。其他阶段都由 Router 和 Engine 自动推进；Router 推进不了时，会向你提问。

## 观察和介入 Worker

在面板上点开任意工单，可以看到它的 Worker 完整、实时的执行过程：每次工具调用、命令输出和报告。

你可以直接介入：

| 想做什么 | 方式 |
|:-:|:-:|
| 调整它正在做的事 | 发送引导消息：当前这批工具调用结束后立即被看到 |
| 在它做完这一轮后追加工作 | 发送排队消息：这一轮结束后再开始新的一轮 |
| 停下当前这一轮 | 打断：工单仍保持打开 |

Worker 空闲时，引导和排队效果一样，都会直接开始新的一轮。你直接给 Worker 发的消息，Router 也会看到一条记录，但不会被唤醒。

直接介入不是审批流程。Worker 本来就不会在每次工具调用前等你确认，介入只是让你在需要时改变方向。

## 重试失败的一轮

模型请求重试用尽或者超出轮次上限时，这一轮会以失败结束，对话视图会显示失败原因。工单的 Worker 失败时，Engine 还会记一份 `failed` 报告并唤醒 Router，由 Router 决定让它继续还是取消工单。

你也可以在面板上直接重试失败的那一轮，Router 和 Worker 都可以。

## 查看花费

```bash
eevee project usage <project>
```

输出项目的合计用量，以及 Router、每张工单和每个模型各自的输入、输出、缓存读写 token 和花费：

```text
合计    输入 182.4k · 输出 21.3k · 缓存读 1200.0k · 缓存写 96.0k · $1.8320
Router  输入 40.2k · 输出 5.1k · 缓存读 310.5k · 缓存写 22.4k · $0.4011
t1「打磨论文草稿」 输入 98.0k · 输出 12.9k · 缓存读 702.3k · 缓存写 51.2k · $1.0250
```

provider 报告了实际计费时用实际金额，否则按模型目录里的价格估算。

## 查看日志

`eevee start` 启动的 Engine 把输出追加到 `~/.eevee/runtime/engine.log`，包括 MCP 连接失败、扩展加载错误和配置问题。实时查看：

```bash
tail -f ~/.eevee/runtime/engine.log
```

遇到问题时，先看 [排查问题](troubleshooting.md)。
