# 02 上下文

每个对话只带完成当前任务所需的内容，其余按需读取。本文只稳定两条产品契约：**持久状态不依赖某个上下文窗口；上下文可以重置或重建而不丢失工作。**

下文的层级、Opening 组成、前缀顺序、保留消息数量与修剪阈值都是当前实现策略，可以根据模型、缓存和实际效果调整，不属于核心领域模型。

## 1. 当前实现的层级

```
┌────────────────────────────────────┐
│ 角色前缀：系统提示词 + 工具列表         │  同一角色配置保持稳定
├────────────────────────────────────┤
│ 开篇：记忆 + 角色专属内容              │  只在创建或 reset 时生成
├────────────────────────────────────┤
│ 后续消息：开篇之后的消息               │  随对话增长，reset 时清空
└────────────────────────────────────┘
```

除此之外的一切（其他工单、旧报告、更早的对话记录、记忆主题笔记、工作目录文件）都不放进上下文，模型需要时用 `read` 按地址去取。

## 2. 当前实现的 Opening

开篇相当于交给模型的“开场材料”：对话一开始（或重置后重新开始）时，它需要知道的全部背景都写在这里，之后不再改变。

| 角色 | 开篇内容（按顺序） |
|:-:|---|
| `router` | 全局 `MEMORY.md`、项目 `MEMORY.md`、项目概况、工单一览（生成那一刻的快照）、交接小结、最近几轮原文 |
| `worker` | 全局 `MEMORY.md`、项目 `MEMORY.md`、工单内容、最新报告、最近 2 条消息 |
| `dreamer` | 全局 `MEMORY.md`、项目 `MEMORY.md`、自上次整理以来新增的对话记录和已结工单清单（只给地址） |

几条约束，都是为了保护缓存前缀：

- **动态内容不进系统提示词**。当前时间、工单状态这类会变的东西只出现在开篇或消息里。Durable 每次请求前都会重新渲染系统提示词段落，一个会变的段落就能让缓存失效。
- **记忆只进开篇**。运行中途记忆被修改，不影响当前对话，下次创建或 `reset` 时自然生效。
- **共享的放前面**。记忆排在角色专属内容之前，同一项目、同一模型的执行对话能共享到工单内容之前的全部前缀。
- **新建和重置得到同样的结构**。新对话的第一条输入就是开篇本身；事后重置时，`handoff` 把新开篇写成重置后的第一条消息。两种情况下上下文都是“角色前缀 + 开篇 + 后续消息”。

## 3. 重置（`reset`）

Durable 的 `reset` 只换掉模型看到的内容，完整记录仍留在存储里，WebUI 上始终是一条连续对话。重置一律由工具发起：工具返回 Durable 的 `control: { handoff: 新上下文 }`，模型写交接内容时用的正是自己还热着的前缀，不需要像内置 compaction 那样换一个提示词全价重读。

| 角色 | 由谁发起 | 新上下文 |
|:-:|---|---|
| `router` | `handoff(summary)` 工具。Router 自己觉得上下文杂乱时调用；或者后续消息超过阈值且 Router 空闲时，引擎投递一条消息请它调用。有长期价值的决策顺手用 `memory` 记下 | `opening(router)` + 小结 + 最近几轮原文 |
| `worker` | `report` 工具。交报告时如果后续消息超过阈值，顺带完成交接 | `opening(worker, ticket)`，其中已经包含刚交的报告 |

**修剪超长工具输出**：只在拼“最近几轮原文”时进行，把超大的工具输出换成“开头 + 省略标记（附 `transcript://` 地址）+ 结尾”。平时从不改动历史消息。

## 4. 按需读取：统一的 `read`

所有角色共用同一个 `read` 工具，按地址读取：

| 地址 | 内容 |
|---|---|
| 普通文件路径 | 工作目录或其他本地文件 |
| `ticket://t12` | 工单内容与阶段 |
| `ticket://` | 工单列表（可按状态过滤） |
| `report://t12#3`、`report://t12` | 某份报告 / 该工单的全部报告 |
| `transcript://<conv>/<entry>` | 某段原始对话记录 |
| `memory://project/<file>`、`memory://global/MEMORY.md` | 记忆笔记 |
| `job://<jobId>` | 后台作业的状态与输出（对应 `jobs/<jobId>.log`） |
| `models://` | 可用模型及其画像（见 [模型接入与画像](../design/05-models.md)） |

- **一律分页**：文本默认 4000 字、上限 8000 字；列表默认 20 项、上限 50 项。`read` 可带 `query` 参数在目标里搜索。
- **处处用地址指路**：截断标记、报告摘要的续读、记忆笔记的来源标注、开篇里的工单一览，全部用这套地址。模型顺着地址一跳一跳展开，就能找回任何旧上下文（链式召回）。执行对话也能直接读依赖工单的报告，不需要 Router 转述。

## 5. 后续可选优化

Router 以后可以根据工作节奏协助管理自己与 Worker 的上下文，例如近期马上要返工时保留现场，长期等待且排错噪音已经无用时选择重置。

这属于实现期优化，不预设固定策略，也不要求核心调度模型依赖它才能正确工作。
