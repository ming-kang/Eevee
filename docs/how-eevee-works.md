# Eevee 如何工作

Eevee 由一个常驻后台的 Engine 进程承载，它管理你的全部项目：每个项目有一个 Router、一组工单、一个项目记忆库，以及保存全部对话和业务状态的持久存储；所有项目另外共用一个全局记忆库。

得益于 Pi Durable，这些状态可以持久化保存，工作在重启后可以继续进行。

## Engine

Engine 是运行在 Node.js 26 上的后台进程，只监听 `127.0.0.1`。命令行 `eevee` 和浏览器面板都通过本地 HTTP 接口与它通信；需要实时推送的客户端可以订阅 WebSocket 实时流。

同一个数据目录同一时刻只能有一个 Engine：启动时先获取 `runtime/engine.lock` 实例锁，再把实际端口写进 `runtime/engine.json`，命令行据此找到正在运行的实例。Engine 先打开全部项目，让中断的工作接着跑，然后才开始接受请求。

## 项目

一个项目对应一项持续的工作，包含：

- 一个 **Router**，是你在这个项目里的主要对话入口；
- 一组 **工单**，每张工单有一个持续的执行对话（Worker）；
- 一个 **项目记忆库**，所有项目还共用一个 **全局记忆库**；
- 一个 **工作目录**，是你自己的目录，产物默认写在这里。

项目的全部对话记录、工单、报告和问题都存在 `projects/<project>/session.sqlite` 里。

## Router 与 Worker

Router 像机场塔台：理解你的目标、安排工单和优先级、处理报告、验收结果、维护长期记忆。它没有写文件和执行命令的工具，不会自己去做耗时的工作，以免挡住全局协调。

工单是一项独立工作的协调外壳，写明目标、输入、验收标准和产物位置，不规定执行步骤。每张工单绑定一个 Worker 对话。Worker 在工作目录里读写文件、执行命令、使用为它启用的 MCP 服务器和扩展，并通过报告和 Router 协同。返工、追加指令、换模型都发生在同一个 Worker 对话里，直到工单结单。

你通常只和 Router 对话，但随时可以打开任意 Worker，查看它的完整过程、直接发消息或打断它。Worker 不会单独给你发通知，需要自动协调的结果都经报告交给 Router。

## 报告与投递

Worker 用 `report` 工具向 Router 汇报。中途报告（`progress`）只记录进展，不唤醒 Router；收尾报告（`waiting`、`ready`、`blocked`、`failed`、`dropped`）结束 Worker 的这一轮，并唤醒 Router 处理。

确定的事情由 Engine 直接投递，不经过 Router 转述：

- 工单验收后，结果投给它 `deliverTo` 里的工单；
- 你回答了某张工单的问题，答案直接投给那个 Worker；
- 后台命令结束，结果唤醒所属的 Worker。

投递有两种方式：**唤醒**会在对方空闲时开始新的一轮；**记录**只把消息写进对话，等对方下一次运行时再看到。完整的投递规则见 [工单与报告](tickets.md#投递规则)。

## 运行与轮次

对话从收到一条消息开始，到给出最终回答、被打断或失败为止，是一次运行（即“一轮”）。一次运行里，模型每请求一批工具调用算一个轮次；[`maxTurns`](capabilities.md#限制每次运行的轮次) 限制的是总轮次数。

Worker 的一次运行如果没有交收尾报告就结束了，Engine 用它最后的回答补一份 `waiting` 报告；如果运行失败（重试用尽、超出轮次上限等），Engine 记一份 `failed` 报告并唤醒 Router；被用户主动打断不算 `failed`。

## 上下文

每个对话只带完成当前任务所需的内容，其余按需读取。模型的上下文分三层：

| 层级 | 内容 | 何时变化 |
|:-:|:-:|:-:|
| 角色前缀 | 系统提示词和工具列表 | 角色的能力配置改变时 |
| 开篇 | 两个 `MEMORY.md` 和角色专属内容 | 只在对话创建或重置时生成 |
| 后续消息 | 开篇之后的对话 | 随对话增长，重置时清空 |

各角色的开篇：

| 角色 | 开篇内容 |
|:-:|:-:|
| Router | 全局与项目 `MEMORY.md`、项目概况、工单一览、交接小结、最近几轮原文 |
| Worker | 全局与项目 `MEMORY.md`、工单内容；重置后另含刚交的报告和最近两轮原文 |
| `dreamer` | 全局与项目 `MEMORY.md`、整理工单（列出待整理记录的地址） |

当前时间、工单状态这类会变的内容不放进系统提示词，记忆也只在开篇里出现，这样同一项目里同一角色、同一模型的对话能共用缓存前缀。

其他工单、旧报告、更早的对话记录、记忆主题笔记和工作目录里的文件都不放进上下文。模型需要时用 `read` 按 [资源地址](addresses.md) 读取，比如 `ticket://t12`、`report://t12#3`、`transcript://1`。截断标记、报告和记忆笔记里都用这套地址指路，模型可以顺着地址找回任何旧内容。

## 重置

上下文变长后，对话可以重置：模型先写一份交接内容，Engine 用新的开篇加上交接内容替换模型看到的上下文。完整记录仍然留在存储里，面板上始终是一条连续的对话。

- Router 调用 `handoff` 工具交接。它可以自己判断时机；上下文超过模型窗口的 [`handoffThreshold`](settings.md)（默认 60%）且 Router 空闲时，Engine 会请它交接。
- Worker 交收尾报告时，如果上下文超过同一阈值，顺带完成重置，新开篇里已经包含刚交的报告。

## 记忆

记忆库是 Git 仓库里的 Markdown 笔记，分为项目记忆库和全局记忆库。`MEMORY.md` 是常驻索引，放在每个对话开篇的最前面；主题笔记由模型按需读取。Router 用 `memory` 工具写入，每轮结束时把改动提交为一个 commit；你用自己的编辑器改过的文件会单独提交为 `user edit`。

Dreaming 默认开启：Engine 定期开一张整理工单，回顾新的对话和报告，合并、订正和清理项目记忆。详见 [管理记忆](memory.md)。

## 后台作业

Worker 的 `bash` 命令运行超过 [`backgroundAfterMs`](settings.md)（默认 5 秒）就转入后台，立即返回一个 `job://j7` 这样的地址，完整输出续写到 `jobs/<job>.log`。Worker 可以先结束本轮、释放并发槽位，命令结束后结果会唤醒它。

后台进程只存在于 Engine 进程里。Engine 重启时，仍在运行的作业记为被打断，并通知所属的 Worker 先检查工作目录再决定是否重跑。工单结单时，它仍在运行的作业会被终止。

## 扩展与角色能力

Eevee 的全部能力都以扩展的形式安装，再由角色按名字选用：

- Eevee 自带的扩展提供 `read`、`write`、`edit`、`bash`、`ticket`、`ask_user`、`report`、`memory`、`handoff` 等工具，每个角色自带固定的一组；
- 每个 MCP 服务器是一个扩展 `mcp.<name>`，`~/.eevee/extensions/` 里的每个文件也是一个扩展；
- 工具搜索（`tool-search`）和代码模式（`codemode`）在需要时自动带上。

可以在面板的设置里为角色启用更多扩展（保存在 `settings.json`），改动立即应用到 Router 和全部未结工单。详见 [配置角色能力](capabilities.md)。

## 持久化与重启

工单、报告和投递总是一起保存，所以 Engine 在任何时刻崩溃或重启，都不会丢失已经保存的工作，也不会重复投递。

重启后，Engine 接着运行被打断的对话，补发尚未送达的投递，结算被打断的后台作业。Dreaming 也按原定的时间继续。

## 界面

- **命令行**：启动、停止 Engine，打开面板，见 [命令行](cli.md)。
- **面板**：`eevee` 打开的本地网页，用来和 Router 对话、回答问题、观察和介入 Worker，以及管理记忆、花费、模型和角色能力，见 [使用面板](web.md)。面板只负责显示和发起请求，所有写入都由 Engine 完成，变化经实时流推送回来。
- **本地接口**：带鉴权的 HTTP 接口和 WebSocket 实时流，见 [接入本地接口](integration.md)。
