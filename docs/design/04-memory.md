# 记忆

## 1. 范围

记忆收录跨会话长期有用的合作经验：

| 记忆库 | 位置 | 写入 |
|---|---|---|
| **项目记忆库** | `~/.eevee/projects/<projectId>/memory/` | Router 的 `memory` 工具、Dreaming |
| **全局记忆库** | `~/.eevee/memory/`                      | 在用户要求时由 Router 写入        |

记忆库借助 Git 来保存版本，但对外只呈现文件与变更，模型无需知晓 Git 内部细节；所有角色都能用 `read` 读取。

| 应当记录 | 应当舍弃 |
|:-:|:-:|
| 用户的偏好与风格 | 交接小结 |
| 用户纠正 | 任务进度与状态 |
| 带理由的架构/实验决策 | 随时能从文件里重新查到的事实 |
| 经验教训 | 密钥与敏感凭据 |

## 2. 格式

- `MEMORY.md`：常驻索引，控制在 200 行以内，存放每个对话都需要知道的核心约定，以及指向主题文件的索引（如 `[[optics-sim]]`）和简要说明。
- `<topic>.md`：按主题存放经验条目，每条附来源地址（如 `ticket://t12`、`transcript://…`）和日期。

## 3. 读取

- **常驻**：全局和项目的 `MEMORY.md` 放在每个对话的开篇最前面，运行中途不变。
- **按需**：主题文件由模型根据索引用 `read memory://project/<file>` 读取。
- 新写入的记忆对之后创建或 `reset` 的对话生效。

## 4. 写入

执行对话只读不写：发现的经验写进报告的 `lessons`，由 Router 或 Dreaming 提炼。

Router 可以编辑、新建记忆文件，查看变更历史并撤销某次变更；撤销本身也记为一次新变更。全局记忆库只允许改动 `MEMORY.md`。

**变更**（`change`）是记忆库的版本单位：一个对话一次运行里的全部编辑合成一次变更，用户在记忆库目录里的手动修改也各自记为变更。变更按时间递增编号，并记录来源（Router、Dreaming 或用户，及相关工单）。

## 5. Dreaming

Dreaming 是后台记忆维护能力，它顺着地址回顾近期记录和现有记忆，尤其是反映真实执行结果的工具输出与报告里的 `lessons`，完成四类整理：

- **合并重叠笔记**：把同类条目整合进清晰的主题文件；
- **剔除临时细节并纠错**：删掉只对单次调试有效的信息，订正被后续执行推翻的旧笔记并注明来源；
- **清理陈旧记忆**：移除已经失效或长期没有价值的条目；
- **补漏与整理索引**：补录漏记的经验，维护 `MEMORY.md`，把过长细节下沉到主题文件。

**触发**：不按固定时钟运行。自上次整理以来积累了足够的新材料（结单的工单或报告里的 `lessons`），且项目空闲（Router、Worker 与后台作业都不在运行）一段时间后，Engine 开一张 `dreamer` 工单；两次整理之间保持最小间隔，同一时间至多一张。阈值属于可调整的运行策略。
