# 06 WebUI 思路

参考 `ming-kang/Sash` 的本地服务模式，系统不打包 Electron，由后台 `Engine` 在 `http://127.0.0.1:<port>/` 直接提供 WebUI。

## 核心思路

UI 以后会继续打磨，现在是初步构想

- **默认安静但不隐藏过程**：面板只主动突出需要人处理的事，也就是待回答的问题，以及进入“等待介入”区的报告（见 [03 工单与调度](03-orchestration.md)）。正常运转的工单不产生通知或待办，但其对话、工具和作业始终可以查看。
- **三栏布局**：左侧项目导航，中间 Router 主对话，右侧工单栏；窗口变窄时右栏先让位。
- **连续主对话**：主区域展示 Router 的连续对话流（`reset` 处只留轻量标记），工具调用等过程默认折叠；有待回答的问题时，提问卡片占住输入框的位置，推荐选项预先选中。
- **Worker 是一等观察与介入界面**：可以点进任意 Worker 查看完整、实时的执行对话和工具结果，直接发送引导、排队消息或打断，并查看报告与后台作业。直接介入不是审批流程，也不要求用户逐条确认工具调用。
- **角色能力配置**：设置界面可以分别为 Router 和 Worker 启用或停用 Devin Search、DeepWiki、MCP 等 Extension，并查看各角色当前能力。默认按角色共享配置，不为每张 Ticket 增加一套设置负担。
- **其他维护能力**：可以查看记忆库的 diff 与 `revert`、`pi.usage` 花费汇总以及模型登录和默认模型设置。

## 当前实现方案

- **单向数据流**：WebUI 只负责显示和发起 RPC，所有写入都由 `Engine` 完成；`Engine` 把 Durable `watch` 的增量更新（ops）经 WebSocket 推给前端，断线重连由 `ConversationTranscript` 补齐缺口。
- **设计 token 分两层**：基础色只在一处定义，组件只用别名，换主题只改映射；明暗跟随系统。
- **识别 Engine 重启**：状态里带上 Engine 每次启动生成的 `bootId`。前端发现它变了，就重新订阅全部数据流，避免拿旧进程的增量去拼新进程的状态。
- **授权**：页面从 `eevee web` 打开的 URL 里取出一次性授权码换成会话，存在 `sessionStorage` 里；直接打开不带授权码的地址时，只显示连接说明（见 [运行时架构](../architecture/00-runtime.md)）。
