# 用户界面

## 原则

1. **简单**：避免分散人的注意力。
2. **布局自解释**：不减少标语、提示文字和次要标签，让界面无需借助说明就能看懂。
3. **正向改进**：持续改善用户体验（UX）、开发者体验（DX）与智能体体验（AX）。

## 1. 定位

面板是用户观察与控制 Eevee 的窗口，与 [00 愿景](00-vision.md) 的原则一致：

- **以 Router 为中心**：项目页的主体是与 Router 的对话，用户通常只需要在这里说话。
- **需要人时才显眼**：待回答的问题、待验收和受阻的工单最先呈现；其余状态安静地放在一旁。
- **一切可观察、可介入**：每张工单、每个 Worker 的完整执行过程与每个后台作业都能打开查看，用户可以直接引导、打断或停止。

## 2. 结构

| 区域 | 内容 |
|:-:|---|
| 导航 | 项目列表与各项目的概况，新建项目，全局搜索 |
| 项目对话 | 与 Router 的对话、待回答的问题 |
| Worker | 一张工单的执行过程，用户可直接发消息 |
| 侧栏 | 工单（按[阶段](03-orchestration.md)归类）、后台作业、工单详情 |
| 记忆 | 项目与全局记忆的文件和变更历史，可撤销变更（见 [04 记忆](04-memory.md)） |
| 用量 | 项目的模型花费与用量 |
| 设置 | 界面偏好、模型与凭据、角色能力、MCP 服务、Engine 状态 |

界面上的工作状态都来自 Engine 的持久状态，刷新或重连后看到的应当一致。

## 3. 配置编辑

配置文件（见 [01 概念](01-concepts.md) §4）可以在面板里编辑，也可以手改，二者等价。
