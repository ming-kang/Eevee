# 用户界面

Engine 在 `http://127.0.0.1:<port>/ui/` 直接提供网页面板；各区域的用法见 [使用面板](../web.md)。

面板需要满足 [愿景](00-vision.md) 中的两条原则：尽量少占用人的注意力；每个工单、Worker 和后台作业都能观测、能介入。

## 1. 原则

1. **简单**：目的、架构、设计和实现都保持简单。
2. **布局自解释**：不写标语、提示文字和次要标签；若一个界面需要借助说明才能看懂，优先改进布局。
3. **正向改进**：持续改善用户体验（UX）、开发者体验（DX）与智能体体验（AX）。

## 2. 提醒

需要用户处理的只有一种情况：有问题等用户回答，不论问题归属某张工单还是 Router。

其他阶段都不打扰用户：待验收和受阻交给 Router，其余正常流转。

- 提醒色只标出待回答的问题，红色只表示受阻和失败，其余状态都是灰色，靠图形区分。
- 项目和工单各自只显示一个状态，取最要紧的那个。

## 3. 布局

主区域始终是一段对话：项目的 Router，或某张工单的 Worker。工单列表、后台作业和工单详情在右栏，记忆、用量和设置从左栏进入。

正文只完整显示用户和模型说的话。工具调用、调度动作、报告、文件改动、命令和作业通知默认折叠成一行，需要时再展开。有问题等回答时，提问卡片占住输入框的位置，推荐答案预先选中。

## 4. 观察与介入

用户可以打开任何一张工单的 Worker，实时看到完整的对话和工具结果；可以发消息引导或排队、打断当前这一轮、查看报告和后台作业、终止作业。

这些都是直接操作，不是审批，面板不要求用户逐条确认 Worker 的工具调用。

## 5. 数据流

- Engine 是唯一写入者，面板只负责显示和发起请求，写完不自己改状态，等 Engine 推送变化。
- 对话和看板都通过 [实时流](../stream.md) 推送；断线重连后补齐缺口，Engine 重启后丢弃全部状态、重新订阅。
- 面板和命令行共用 `src/api/contract.ts` 里的 [本地接口](../integration.md)，面板能做的事，脚本和 Agent 用同一套接口也能做。
- 通知、工具结果、失败原因和错误都是结构化数据，面板按用户选择的语言措辞。

## 6. 视觉

- **安静**：层次靠明度和阴影区分，不用描边；只有正在运行的条目和正在输出的回答会动，并遵循系统的减弱动态效果设置。
- **颜色只表达含义**：中性色不带色相；强调色只用于焦点、选中和开关的“开”，不表示状态。

颜色按用途命名，具体取值由主题决定；颜色和层级、尺寸、字号、动效一起定义在 `web/src/styles/tokens.css`。
