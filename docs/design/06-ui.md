# 用户界面

## 原则

1. **简洁**：减少注意力分散，利于心流状态。
2. **布局自解释**：减少标语、提示文字和次要标签，让界面无需借助说明就能看懂。
3. **注重体验**：User/Developer/Agent Experience.

## 1. 定位

面板是用户观察与控制 Eevee 的窗口，与 [00 愿景](00-vision.md) 的原则一致：

- **以 Router 为中心**：项目页的主体是与 Router 的对话，用户通常只需要在这里说话。
- **需要人时才显眼**：待回答的问题、待验收和受阻的工单最先呈现；其余状态安静地放在一旁。
- **一切可观察、可介入**：每张工单、每个 Worker 的完整执行过程与每个后台作业都能打开查看、管理。

## 2. 结构

面板分为左中右三栏：

| 区域 | 内容 |
|:-:|---|
| 左栏 | 总览入口、项目列表与各项目的汇总状态、新建项目、全局搜索、控制面板入口；不展开工单 |
| 中栏 | 总览，或与 Router 的对话及待回答的问题 |
| 右栏 | 项目的工作区：工单（按[阶段](03-orchestration.md)归类）、后台作业，以及打开的对象 |

- **总览**：跨项目的「现在」，按阶段分列：待处理（待回答、待验收、待批准的记忆变更、受阻与失败）、运行中、最近完成；可按项目筛选。打开其中一项即进入所属项目，并在右栏展开它。
- **左栏汇总状态**：一个项目只显示最需要注意的状态，优先级依次是待处理、失败、未读的完成、运行中，忙碌的项目不会掩盖等待用户的工单。
- **右栏工作区**：以标签页承载 Worker 的执行过程、工单详情、后台作业、产物与文件预览、变更等对象。观察或引导 Worker 时，中栏仍是 Router 对话；需要更大空间时右栏可以最大化。
- **控制面板**：以弹窗打开，不打断当前项目，汇集记忆（项目与全局记忆的文件和变更历史，可撤销变更，见 [04 记忆](04-memory.md)）、用量与花费、模型与凭据、角色能力、MCP 服务、界面偏好和 Engine 状态。待批准的记忆变更同时列入总览的「待处理」，从那里直接打开对应分区。
- **一致的状态语言**：同一对象的阶段与运行状态在左栏、总览、右栏和对话内的引用中以同一种方式呈现。

界面上的工作状态都来自 Engine 的持久状态，刷新或重连后看到的应当一致。

## 3. 对话

- 已结束的回合收起过程，只留下回复；进行中、中断或失败的回合保持展开。
- 进行中的回合可以停止；尚未送达的消息可以撤回或修改。
- 问题可以先放到一边，已结束的问题可以回看。
- Router 派出的工单在对话中以引用呈现，并显示其实时阶段，点击即在右栏打开。
